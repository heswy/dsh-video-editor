# DSH Video 前端设计规划

日期：2026-10-17。方向草案 v0.1。

> P0-A 后更新：用户已同意首版使用顶部靠左原生入口，居中作为后续优化。下文关于中轴的描述保留为最终视觉目标；P0-B 不通过 overlay/替换宿主 header 追求居中。两处模式胶囊优先保持左侧位置、尺寸与形态连续。

用户明确要求：优美、精致、优雅，考虑液态玻璃，动效丰富。本文把该偏好转化为可实现、可验收的视觉与交互规格；具体数值是设计起点，尚未经真页面视觉验证。它不改变 P0-A 的只读调查范围，也不意味着用户已经认可每个布局细节。

## 1. 设计概念：玻璃上的剪辑台

第一眼是宽阔的画面，第二眼是轻盈的工具，开始操作后才感知细致的反馈。

空间由三种材质组成：安静的实底工作面、低反差磨砂面板、浮在上层的玻璃控件。视觉深度来自材质和间距，内容层级来自尺寸与排版。画面拥有最强色彩和对比；控件通过清晰轮廓与少量强调色获得辨识。

三个标志性细节：

- 顶部「普通｜视频」是一枚轻薄玻璃胶囊，选中底片平滑移位，文案与位置稳定。
- 预览下缘的播放条像一条悬浮的玻璃尺，光感轻微，数字和按钮始终清晰。
- 用户选中画面中的对象，右侧出现同名上下文；AI 修改完成后，以一次短暂描边和修改摘要说明哪里变了。

气质关键词：精密、清透、电影感、从容。视觉情绪主要由作品本身贡献。

## 2. 宿主与模式

普通模式完整保留 DSH 原界面和主题。视频模式进入独立主内容视图，DSH 左侧导航仍属于宿主；插件不重画第二套宿主侧栏。

顶部切换居主内容区域的视觉中轴，不按全窗口中轴猜坐标。项目名在左，主要导出操作在右；它们属于视频模式的项目栏。切换的实际 Slot、标题栏拖拽与双击区域须由 P0 契约证据确认。

模式胶囊建议宽 176–208px、高 36–40px，两段等宽；可点击面积扩展到至少 44px 高，避免侵入窗口拖拽区。图标可选，必须有「普通」「视频」文字。支持键盘导航与可读选中状态。语义按实际切换机制选 tabs 或 navigation，不给纯展示按钮伪造 tab 关系。

普通→视频保留同一个切换锚点；视频→普通恢复之前会话、草稿与滚动状态。快速连续切换时始终服从最新选择，不排队播放上一段动画。

## 3. 工作区结构

以下结构以**插件获分配的内容宽度 W**为准，已扣除 DSH 侧栏；不是全窗口断点。

```text
DSH 顶部区域             [ 普通  |  视频 ]
┌──────────────────────────────────────────────────────────┐
│ 项目名 · 保存状态                 撤销 / 重做       导出 │
├────────────┬─────────────────────────────┬───────────────┤
│ 场景 / 素材│                             │ AI / 属性     │
│            │          主画面             │               │
│ 01  开场   │                             │ 当前选择      │
│ 02  产品   │       对象选择 / 安全区      │ 意图与修改    │
│ 03  CTA    │                             │               │
│            │   [时间码 · 播放 · 适配]    │ 输入区固定底部│
├────────────┴─────────────────────────────┤               │
│ 时间线：Scene / 叠加元素 / 音频          │               │
└──────────────────────────────────────────┴───────────────┘
```

一个主要画面、一个左侧资源区、一个右侧上下文区。右栏用「AI / 属性」切换共享空间；面板切换不清空输入、滚动位置或对象选择。时间线位于左侧资源区与主画面下方，右侧 AI 贯穿高度。

### 尺度与响应

| 可用宽度 | 布局策略 |
|---|---|
| W ≥ 1280px | 左栏 208px，右栏 304px；内容外边距 16px，列间距 12px；剩余给画面 |
| 1040 ≤ W < 1280px | 左栏 176–192px，右栏 280px；适度收紧间距，允许用户收起左栏 |
| 800 ≤ W < 1040px | 左栏折叠为可展开资源入口；右栏与画面互斥扩展，避免三栏同时挤压 |
| W < 800px | 画面优先；场景/AI/属性成为单个可关闭抽屉，时间线可折叠；提示扩大窗口以精细编辑 |

项目栏 48–52px；时间线默认 184–220px，可拖高；上部画面区建议至少 240px 高。低高度窗口先折叠时间线及次要工具；不能靠缩小全局字体适配。拖拽分隔线有 8px 以上有效命中区和键盘调整途径。

预览按作品比例适配，横屏/竖屏都居中，周围有呼吸空间；不裁掉作品来撑满面板。查看作品时可用专注模式收起两侧，退出后原样恢复。播放条位于作品外的下缘留白中；若空间不足则降为固定下栏，不遮挡字幕或裁进导出内容。

## 4. 视觉材质

### 四层表面

| 层级 | 用途 | 视觉规格起点 |
|---|---|---|
| 工作底面 | 工程、画面周边 | 跟随宿主背景，中性、无动态纹理；不从视频采色污染色彩判断 |
| 实用面板 | 场景列表、AI 正文、属性、时间线 | 高不透明度，柔和分隔；文本区稳定，无滚动折射 |
| 磨砂玻璃 | 胶囊、播放条、上下文工具条 | blur 16–24px，明确底色、细内高光、低扩散阴影；一处独立边缘即可 |
| 临时浮层 | 菜单、导出设置、命令面板 | 更实的底色与清晰边界；与触发点保持空间关系 |

这是浏览器中的玻璃视觉近似，不宣称获得 Apple 原生 Liquid Glass 的光学行为。第一版不实现全屏折射 shader、实时背景采样或追随鼠标的持续高光。

玻璃控件之间避免重叠；文字不随透过内容一起模糊。高对比画面经过玻璃后，控件仍有足够底色保持可读。画面预览本身不施加 UI blur、染色、圆角滤镜或阴影来改变作品内容；外侧框架可圆角。

### 浅色与深色

- 浅色：接近宿主的暖中性底、瓷白面板、轻薄银灰分隔。玻璃明亮但边缘可辨。
- 深色：接近宿主的石墨底、稍提亮的面板、克制的边缘反光。避免大面积纯黑与发光字。
- 默认跟随 DSH 主题，不进入视频模式就强制切黑；视频周边可以有局部中性观看底。
- 强调色取宿主可用的主色，用于当前模式、当前选择和主要操作；同一屏避免多个竞争性强调色。
- AI 状态以图标、文字和语气区分，不设计独立紫色霓虹体系；音视频轨道采用稳定类别标记，不能只靠颜色识别。

### Token 接入

实现前由 inspection 查到**准确存在**的 DSH token。插件内部可声明语义别名，如 `--video-surface`、`--video-text-secondary`、`--video-focus`、`--video-glass-fill`，映射宿主 `--dsw-alias-*`；示意名不代表已存在的宿主 API。

控件颜色不得到处写死 hex。玻璃透明度、blur、圆角、边界和动效独立成 token；字体复用宿主栈，避免加载第二套网络字体造成割裂和首次渲染跳动。视频作品自己的字体与颜色独立管理。

### 排版与几何

- 采用 4px 基础步进，常用空间 4 / 8 / 12 / 16 / 24 / 32px。
- 工程名 16px/medium，分组标题 12–13px/medium，正文与输入 14px，时间码与辅助标签 12px；中文正文行高约 1.5。随宿主字号缩放。
- 常用字重 400/500，必要标题 600；时间码和参数用等宽数字，滚动播放时不抖动。
- 主面板外框半径 14–18px，媒体缩略图 8px，普通输入 8–10px，模式/播放条使用胶囊；不用每个小分组套圆角卡片。
- 图标统一视觉语言，16–18px、约 1.5px 描边。功能按钮保持一致命中面积，图标按钮提供标签与 Tooltip。
- 层级通过间距、留白和材质表达，避免正文过浅、分隔线过多、每个按钮都有阴影。

## 5. 页面与关键状态

### 首次进入 / 无工程

中央是一句简短邀请「从一个想法，开始一支影片。」和一个明确的创建入口。可通过创建入口附加 Logo、截图与简介。已有项目用少量真实缩略图列出；无真实项目时不造示例作品来填满界面。

未支持的能力不出现可点击假按钮。P0 只显示真实可用的入口和准确阶段说明，不用静态时间线冒充编辑器。完整空状态随项目创建能力在后续阶段交付。

### 已打开工程

- 左栏「场景 / 素材」切换。Scene 是带序号、缩略图、名称和时长的紧凑行；选中时窄标记与底色呼应，避免整行强光。
- 主画面承担视觉中心，选中框细且明确，拖动时显示对齐辅助线；对象选中框、操作手柄、坐标提示都不进入视频导出。
- 右栏默认 AI。当前 Scene、对象或时间段以紧凑上下文条出现，用户可移除指定对象或回到整片上下文。
- 「属性」只显示当前选择可编辑的参数；不支持的图形对象给出原因及 AI 修改入口。
- 时间线以 Scene 为第一层，展开后看对象与音轨；标签和剪辑面优先清晰，波形、缩略图不是装饰纹理。

### AI 正在创作与修改

展示真实阶段，如「构建第 2 幕」「检查关键帧」；没有真实进度时只显示阶段与已完成项，不编造百分比或倒计时。

有有效预览后保留上一版，局部变化就绪再替换；生成失败仍能查看旧版。只有针对旧修订有意义的操作才暂时限制，并显示原因。AI 写入与用户编辑冲突必须显式提示，不能用漂亮过渡掩盖覆盖。

完成后给一条简短摘要，例如「第二幕：减少粒子、收紧标题入场」，可查看修改、撤销；标注过的对象描边一次后回到正常。没有实际变更时不播放“完成”效果。

### 导出

从右上导出入口展开设置层，先显示分辨率、帧率、音频与输出位置，再开始。进行中显示真实阶段、已渲染帧和取消操作；完成显示文件与打开入口。失败保留设置和错误原因，允许重试。

导出完成是安静的完成状态，不放礼花、不抢焦点、不替用户打开其他应用。界面玻璃、浮层和编辑辅助线必须完全排除于成片。

## 6. 动效谱：丰富而从容

时长为起点；先保证操作立即响应，再让视觉收尾。同一动作的一组元素共享节奏，避免每个控件各自弹跳。常驻工作区空闲时保持静止。

| 触发 | 具体运动 | 时长起点 | 中断 / 降级 |
|---|---|---|---|
| 点击普通/视频 | 选中玻璃底片平滑横移，轻微压缩后归位；页面整体淡入并上移 6px | 选中 220ms；页面 260ms，错开约 40ms | 最新点击覆盖前次；减少动效时即时切换或 ≤80ms 淡化 |
| 首次进入编辑视图 | 项目栏先稳定，画面随后，资源和工具最后显现；单次序列总长 ≤360ms | 每组错开 25–35ms | 不让工具等待动画才可点击；返回时不重播整段入场 |
| 菜单 / 浮层 | 从触发点附近出现，scale .98→1，位移 ≤4px，透明度过渡 | 入 180ms / 出 120ms | 锚点隐藏则关闭；窄窗口先调整位置而非越界 |
| Scene 切换 | 保持舞台框架，替换已就绪画面；选中标记连贯移动 | 140–180ms | 媒体未就绪保留旧帧并提示；不交叉混合影响精确比较 |
| 对象选择 | 选择框明确出现；属性摘要替换，相关工具条就近出现 | 100–140ms | 不移动作品对象，不等待动画才允许拖拽 |
| 展开 AI / 属性 | 旧内容先退，新内容在同一空间显现，保留栏宽 | 出 90ms / 入 140ms | 快速切换取消旧过渡；输入草稿保留 |
| 素材拖放 / Scene 排序 | 原位占位，拖动对象有轻微提升，目标位显示清晰插入线 | 提升 100ms / 落位 160ms | 拖动目标跟手，无插值延迟；Esc 恢复原位 |
| 时间线吸附 | 边界接近时出现辅助线与目标提示，松手后确认位置 | 辅助反馈 80ms | 播放头、拖动位置和时间码直接跟随；禁止弹簧过冲 |
| AI 局部修改完成 | 对象轻描边一次，摘要到位，随后消退 | 总计 500–700ms，非阻塞 | 播放或用户正在拖动时省略描边；不用闪白全屏 |
| 保存 / 导出状态 | 小图标及文案原位替换，整体宽度预留 | 120ms | 状态文本即时准确；屏幕阅读器只播阶段变化 |

曲线建议：精确反馈用快速 ease-out（如 `cubic-bezier(.2,.8,.2,1)`）；模式底片可以用受控弹性，但无可见大幅回弹。弹性只用于非精密的装饰性反馈，绝不用于时间、坐标和参数。

“多动效”体现在交互覆盖面和细节完整度：hover、press、focus、选择、状态、面板、拖放都设计；同一时刻只让少量主要变化吸引注意。不做环境粒子、循环漂浮、自动流光或反复 shimmer。

用户视频内的动画由作品时间控制，与编辑器 UI 动效完全分离。暂停、抽帧或 scrub 时不得因 UI transition 改变该时刻画面。

## 7. 可读性、性能与降级

- 正文目标对比度 ≥4.5:1，关键控件边界/状态 ≥3:1；检验实际视频背后的玻璃合成结果，不能只检验基础色值。
- 可见 focus、键盘切换、菜单 Escape、对话框焦点回归、拖拽替代操作。提示不能只出现在 hover。
- 尊重 `prefers-reduced-motion`；可提供“简化界面效果”选项。减少透明度/增强对比若没有可靠宿主信号，不能宣称自动跟随系统，提供插件内降级开关并持久化。
- 不支持 backdrop-filter 或帧耗超预算时，自动/手动切到高不透明度实底；内容层级、选中与操作仍完整。
- 主要过渡使用 transform / opacity；不持续动画 blur、backdrop-filter、box-shadow 或大型布局属性。面板布局先更新，必要的视觉过渡不能阻塞交互。
- 暂定同屏独立 backdrop-filter 区域 ≤3，禁止玻璃嵌套；导出期间可简化效果，但不修改用户作品。
- 在目标机器真实播放时评估 UI：以 60Hz 下无连续掉帧、输入反馈 <100ms 为目标，不把目标写成已测事实。优化优先级为播放/拖动正确 → 点击响应 → 材质光感。
- 几十个以上 Scene/轨道时考虑虚拟化，缩略图按需生成；玻璃合成不可触发整条时间线重绘。

## 8. 实施节奏与验收

1. **P0-A 契约**：确认顶部、主视图与状态保持。设计不据此猜测可用 API。
2. **P0-B 基础**：真实顶部切换、主题、空状态、视图保持；只交付已支持能力，先验证玻璃胶囊的基本材质和交互。
3. **P1/P2 工程编辑**：实际预览、场景/素材、共享上下文栏、基础时间线与属性；先清晰可用，再添加对应动效。
4. **P3 创作闭环**：真实 AI 阶段反馈、修改摘要、选中对象上下文及导出；动效与实际事件绑定。
5. **视觉精修**：在真宿主中调整材质、光感、间距与节奏，检查明暗、窄窗、字体缩放、快速中断和资源释放。

视觉验收至少留存：浅色/深色无工程、编辑工程、对象选择、AI 修改状态、导出设置；短录屏覆盖模式切换、Scene 切换、拖放/吸附和简化动效。所有截图/录屏来自真实安装页面，未实现阶段留空，不以概念图替代功能验收。

评审时回答：第一眼是否看向作品？正文是否易读？玻璃是否有合理层级？每个动效是否解释状态？反复操作是否疲劳？切换是否丢状态？若关掉动效和透明，是否仍是一套清楚好用的编辑器？

## 9. 参考与设计取舍

Apple 将 Liquid Glass 作为浮于内容之上的控制/导航层，强调材质、运动与内容的关系；本方案借鉴层级与连续性，实际实现遵守 DSH 的 Web Slot 和主题约束。[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。

本次运行 UI/UX 技能的设计检索返回了移动端 brutalism、粉色与循环 marquee，和用户要求的精致桌面编辑器不匹配，未采纳。排版采用宿主字体而非另建品牌字体；这是保持 DSH 原生感与降低成本的明确取舍。

待真页面确认：宿主 theme token、玻璃合成开销、顶部定位、Right rail 与现有会话上下文接线。本文尚无代码、效果演示或实机性能结论。
