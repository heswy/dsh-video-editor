## 1. 本轮交付

本轮统一交付五项：

1. 独立音轨显示可辨识、随缩放变化的真实波形。
2. 视频片段内部显示随时间变化的连续缩略图条；导入视频和 AI 场景都支持。
3. 视频有原声时，在同一片段底部显示波形；原声默认不拆成额外音轨。
4. 视频与音频采用统一的顶部名称条，视频蓝色、音频绿色，状态与操作层级一致。
5. 含原声的视频支持右键“分离音频”，生成可独立编辑、与视频对齐的音频片段。

以上五项纳入1.0.0发布前范围。现有冻结包保留回滚，但实施开始后不再作为最终发布包；完成后重新冻结、构建、安装和验收。

## 2. 视觉与交互

| 类型 | 顶部 | 主体 | 底部 |
|---|---|---|---|
| 独立音频 | 名称，单行截断 | 绿色底、浅色真实波形，占据主要高度 | 淡化/选择边界保持清楚 |
| 视频含原声 | 轻量名称条 | 连续真实缩略图 | 单独的原声波形带 |
| 视频无音频流 | 轻量名称条 | 连续真实缩略图 | 不预留波形空带 |
| AI 场景 | 轻量名称条 | 该场景自身的连续采样图 | 当前场景契约不嵌音频，无原声带 |
| 图片 | 轻量名称条 | 同一静态图片填充 | 不显示波形 |

- 普通视频轨建议内容高度约76px：标题16px、画面约40px、原声约16px及边距；无原声时画面占据余下区域。同轨按是否含原声统一布局，避免片段边缘参差。
- 独立音轨约56px：标题16px，剩余区域画波形；保留紧凑模式（约34px），缩减标题/图像高度但不挤压操作手柄。具体数值由宽/窄、深/浅主题截图确认。
- 缩略图以约70–100px宽的小格排列，不画成真实切口；片段仍是一个可选、可拖动对象。
- 短片段只显示一张图，极窄片段优先选择边框和裁剪手柄，避免强行塞入名称。
- 视频静音：原声波形保留并变暗；关闭画面：缩略图变暗，原声保持独立状态。片段静音与轨道静音都体现到波形状态。
- 加载中使用中性色块，失败保留名称和正常剪辑能力；不增加常驻按钮、文字和新的面板。
- 图像和Canvas层不接管鼠标事件；选择、裁剪手柄、拖动悬浮、落点、播放头的层级与命中优先级保持明确。

## 3. 现状与实现边界

现有 `assets.mjs` 将整个音频生成固定320×80 PNG；客户端将其拉伸并裁剪。`asset.derive` 现有thumb只取一帧，不能直接承担胶片条；媒体路由也只接受assetId，AI场景没有该媒体assetId。

因此不靠扩大旧PNG或重复单张封面实现：新增独立的时间线派生资源服务，复用资产解析、真实路径校验、子进程管理和认证路由。旧素材库缩略图接口保留兼容，避免拖累此次范围。

缓存和图形是派生视图，不写timeline内容，不制造revision或撤销记录；删除缓存后可重建。生成、播放、导出继续使用原始作品数据。

## 4. 波形数据

- Worker流式解码为受控采样率的PCM，逐时间桶计算峰值及RMS，不一次载入完整PCM。
- 双声道用各通道绝对峰值的最大值作为合并包络，避免反相相加后抵消；V1只显示一条合并波形。
- 建立多分辨率峰值层级；客户端按实际可见像素选择层级，用Canvas画上下对称波形，避免每个采样点生成DOM。
- 低音量内容采用整份素材一致、有限幅度的显示增益和柔和非线性映射；裁剪与横向滚动不会让相同声音突然变高。显示增益不改播放或导出音量。
- 不逐窗口归一化，不把底噪无限拉满；真正静音保持平线，瞬态仍有峰值，稳定持续音允许呈现稳定包络，不伪造节奏。
- 名称、波形和淡化控制分层，波形不再被压成细线；片段/轨道音量和淡化可在绘制时体现，素材峰值缓存不重算。波形仅辅助编辑，不标榜为精确LUFS或输出电平表。
- 视频原声使用同一音频解码与波形数据管线；依据现有hasAudio能力选择生成。无音频流的视频不请求波形；有音频流但内容静音的视频显示真实平线。

## 5. 连续缩略图

### 导入视频

按源时间抽帧生成小尺寸图集与时间索引，复用FFmpeg解码。只请求片段可见区域所需采样，优先覆盖代表帧，再补连续采样；同一来源被多片段引用时共享源时间缓存。

### AI场景

由受控离屏浏览器加载当前片段的场景HTML及声明资源，用现有确定性时间驱动定位采样；复用一次页面加载批量采样，不为每张图启动Chrome。

必须渲染片段自身，而非整条时间线合成结果：下层轨道的缩略图不能被上层遮挡。复用渲染器并不意味着复用整片frame接口输出，需要增加场景级采样适配。

AI场景缓存按场景内容哈希、资源指纹、画布尺寸、渲染器版本及采样时间标识。AI修改场景后，旧图不能回写覆盖新图。

### 对应规则

统一映射：`源秒 = sourceInFrame / sourceFps + (时间线帧 - startFrame) / timelineFps × speed`；不可混用素材fps与时间线fps。场景使用自身时间基准，并复用引擎对合法边界的裁定。

- 移动只改变位置，不重做已有源时间缓存。
- 裁剪、拆分、复制可复用缓存，但图像和波形必须对齐各自sourceInFrame。
- 变速改变显示映射，不改源采样真实性；分级采样不足时后台补图。
- 不用转场后的整片画面替代片段自身缩略图；转场保留其独立叠层标记。

## 6. 队列、缓存与接口

- 按“可见片段优先，邻近区域预取”的顺序调度；滚动/缩放中先复用现有缓存，停止后补更高精度。隐藏窗口不持续采样。
- AI场景采样初始并发1，媒体派生初始并发最多2；暂停或让位于播放准备/正式导出。限制单请求时间窗、采样数、输出尺寸、超时与响应字节，页面任务支持取消。
- 多分辨率波形与缩略图分批返回，不等待长素材全部处理完才显示第一屏。初始建议单批最多24张，每张最长边160px；上线前依据测量调整，不作为未经实测的性能承诺。
- 项目内专用cache保存数据：原始媒体按内容哈希，场景按上述指纹；格式与算法版本入key。原子写入、重复请求合并、失败任务可重新调度。
- 设置缓存预算和LRU清理（初始每工程128MiB，总预算512MiB），只清理由本服务登记的派生文件，绝不删素材、作品、导出或旧安装包；活跃响应被引用时不清理。
- Host负责项目归属与生命周期；worker负责解析与采样；客户端只拿结构化数据和不透明缓存标识，不提交或接收任意磁盘路径。
- 拟新增UI-only派生方法：`timeline.visuals.request/status/cancel`，参数为projectId、expectedRevision、clipId、可见区间、受限分辨率档位；返回任务/有界数据与资源标识。正式字段在实现前冻结契约测试。
- 新增受认证派生资源读取路由，按项目、缓存清单和标识取文件；沿用realpath边界与流式响应。AI工具无需直接调用这些方法。
- 响应带revision和内容指纹；迟到、工程切换及销毁后的结果直接丢弃。取消任务不能取消另一个视图正在共享的同源任务。

## 7. 实施顺序与改动面

1. 先完成统一源时间映射、波形提取/分辨率层级和缓存生命周期，验证静音、反相立体声、瞬态和低音量。
2. 接入独立音轨和视频原声的波形，验证裁剪/拆分/变速与静音状态。
3. 接入导入视频、图片及AI场景的缩略图管线，验证片段隔离和缓存失效。
4. 实现分离音频原子操作、右键入口，验证混音一致、无重复原声、撤销/重做和失败回滚。
5. 完成统一名称条、颜色和图层布局、可见区域调度、紧凑/窄屏模式、失败与取消回归。
6. 统一CR、固定包验证，再安装最终候选交用户验收；五项作为同一轮交付，不把仅完成导入视频当作AI场景也完成。

主要文件：`client.js`、`host/bridge.js`、`host/media-routes.js`或新的受控派生路由模块、worker派生服务/任务管理、新增测试及`scripts/stage-dev.mjs`的RUNTIME_PATHS。引擎协议/能力有变化时同步client/worker版本对；不单改界面版本。

## 8. 验收标准

| 项目 | 必须通过 |
|---|---|
| 音轨波形 | 低音量有结构、静音为平线、瞬态可辨、反相立体声不抵消；短/长素材均可用 |
| 视频缩略图 | 导入视频及AI场景均有按时间变化的真实图；上下轨隔离，不能重复一张图冒充采样 |
| 视频原声 | 有声视频显示波形，无音频流不留空带；静音/画面关闭分别作用 |
| 分离音频 | 起点/入点/时长/变速/音量/淡化一致，无双重播放；原子撤销/重做；无声、静音、冲突、取消与失败路径正确 |
| 编辑对应 | 移动、trim、split、复制、变速、撤销/重做后图像和波形时间正确；不改原始内容 |
| 生命周期 | 连续缩放/滚动、切换工程、AI更新、缓存清除、失败重试、卸载/取消，无陈旧回写或孤儿进程 |
| 导出与数据 | 开关显示前后作品revision、原素材及导出画面/声音不被派生任务改变 |
| 性能 | 20s和120s混合工程、大素材；记录首屏可用时间、缓存命中、峰值RSS/磁盘、播放/拖动响应；不因采样阻塞UI |
| 视觉 | 深浅主题、340px窄工作区、短片段/长名称、静音与选中、普通/紧凑模式截图验收 |
| 固定包 | 新增模块实际入包；固定包跑同样回归；原生DSH核对加载的Client/Host/worker版本一致 |

短期不扩展：左右声道分轨、人声/伴奏AI分离、频谱编辑、自动字幕、采样库、供应商面板与原始音频增强。“分离音频”仅提取视频已有音轨，不是AI人声分离。

## 9. 交付与不确定性

最大不确定性是复杂AI场景的离屏采样成本，先做窄范围技术验证；若性能不达标，调整采样密度和调度，不能静默退回重复封面并宣称完成。

本轮不承诺未实测的工期或帧率；交付证据分别标注单元/Host/浏览器/真实渲染/原生宿主。方案批准前不修改现有实现、不替换安装、不宣告当前冻结包已满足本方案。

## 10. 统一片段样式与分离音频

### 10.1 片段样式

- 视频使用低饱和蓝色名称条和边框，音频使用绿色；兼容宿主深浅主题，不以高饱和大色块争夺预览焦点。
- 视频：顶部名称条 → 中部连续缩略图 → 有原声时底部波形带。音频：顶部名称条 → 主体波形。名称不再直接压在缩略图或波形中央。
- 选中使用清晰描边；悬浮轻微提亮；拖动保持“拎起”的阴影、跟手预演和原位占位。静音用扬声器关闭状态及波形变暗，关闭画面用摄像机关闭状态及缩略图变暗，不能只靠颜色区分。
- 轨道名后沿用开关：视频轨为摄像机＋扬声器，音频轨为扬声器，提供明确tooltip和可访问名称；右键菜单继续保留轨道操作。片段右键与轨道右键按命中对象区分。
- 默认轻量显示，不加入常驻技术信息；源文件路径、采样状态等放到按需提示或诊断中。

### 10.2 用户流程

1. 右键含原声的视频片段，选择“分离音频”。右键本身不移动播放头。
2. 在可用音频轨创建对齐片段；没有无冲突位置时自动在音频轨区域新增轨道，并使结果可见、选中生成的音频。
3. 视频保留画面、位置、时长；只关闭该视频片段的原声，不静音整条视频轨。音频命名为“原名称 · 原声”。
4. 新音频可独立移动、裁剪、切分、变速、调音量、淡化、静音和删除；分离后默认独立，不自动跟随视频后续移动或裁剪。
5. 一次撤销恢复分离前状态；一次重做恢复同一分离结果。删除独立音频后不自动恢复视频原声，避免意外发声；可撤销删除，或在视频片段设置中重新开启原声。

### 10.3 内容与声音一致性

- 只分离当前视频片段实际引用的源区间，保留时间线起点、源入点、时长、变速、片段音量与淡入淡出。不把完整源视频声音无条件铺到时间线上。
- 优先直接引用已有视频素材的音频流；若现有音频片段协议不支持，则生成受管理的音频素材。实现前先冻结契约，不修改原视频，也不为每次分离复制大文件。
- 提取结果若作为素材登记，出现在素材库且标明来源；创建片段是本次操作的一部分，不要求用户再手动上轨。派生缓存与正式素材生命周期必须分开。
- 分离前后的可听混音应一致：视频片段已有静音状态、所在视频轨静音状态均折算为新音频片段的初始有效静音状态，不改变目标音轨或其它片段的静音。目标轨优先选择未静音且无冲突的轨道，否则新建；项目级音量继续只作用一次。
- 分离完成后视频隐藏原声波形带，缩略图填满剩余高度；新音频显示正常或继承后的静音状态。普通静音仍保留变暗波形；主动重新开启视频原声时恢复波形。用户主动重新开启视频原声可能造成叠加，设置处需提示原声已分离。
- 使用稳定的来源关联防止重复点击/请求重试生成多份音频；已有有效分离结果时禁用重复动作并可定位已有结果。删除结果后允许再次分离，不把此前用户手动移动后的音频强制拉回原位。

### 10.4 边界、事务与AI调用范围

- 无音频流的视频：菜单禁用并提示“此视频无音频”；含音频流但内容静音仍允许分离；AI场景和图片无此动作。
- 当前V1默认分离播放器实际使用的那一路音频；多语言/多音频流选择器不在本轮范围，不静默混合所有流。
- 不覆盖已有片段、不隐式移动其它音频。达到轨道上限时明确提示；处理失败或取消时不改变视频原声、不留下半个分离结果或未引用的正式素材。
- 新音轨（如需）、素材登记（如需）、音频片段和关闭视频原声作为一个原子编辑事务，共享revision检查、一次撤销/重做及持久回执；耗时提取先准备，提交时重新校验当前revision和源片段。
- 本轮以用户在片段右键菜单手动分离的完整流程作为交付和验收范围。不拦截AI通过现有编辑能力调用同一分离操作，不新增AI专用入口、面板或供应商。AI调用仍遵守工程归属、revision、幂等、原子事务及失败保护；本轮不保证AI目标理解、调用成功率及端到端效果，也不将其作为发布验收项。
- 同源视频被多个片段引用时，缓存可共享，但分离状态按片段维护，不能误关其它片段原声。

## 11. 用户实测反馈：媒体播放、预览声音与点击定位

2026-10-24 用户要求更新方案并修复安装：

- 导入视频从中间跳转黑屏、画面不更新及播放卡顿：显式跳转合并，元数据就绪后补定位；等待当前seek完成再处理最新目标，正常播放不逐帧重写currentTime，只校正明显漂移。用长GOP视频、暂停前后seek、连续seek、轻微解码延迟验证真实解码画面，不以时间数字变化替代画面正确。
- 声音按钮明确为“开启作品预览声音”，提示只播放作品视频原声和音轨，不影响导出或轨道静音。保留浏览器需用户手势的激活兜底，激活后隐藏，不增加另一AI面板。
- 点击视频/音频片段内任一点或轨道空白，播放头移到点击时间；选中片段同时按点击位置定位，不再一律跳片段起点。复用标尺坐标、缩放、滚动和帧对齐，点击暂停播放，拖动/trim完成不触发额外跳转。右键、开关、轨道名不误定位。
- 这三项修复按单独回归证据交付；前面波形/连续缩略图及分离能力的方案和实现状态分别报告，不把尚未实现的视图能力写成通过。安装使用新的固定提交/摘要，旧1.0.0包保留回滚。

实机追加：原生协议的Origin:null媒体请求与HTTP路径行为不同，媒体播放验收必须包含dsh-app原生页面。复用受限本机快照能力地址及Range/CORS，不降低iframe沙箱、不暴露宿主全局凭据。

## 12. 发布前验收场景

1. 导入含原声视频：能看到连续变化的缩略图和底部波形；无音频流视频不出现空波形带。
2. 对低音量、静音、瞬态、反相立体声及长音频检查真实波形，缩放/滚动后同一位置形状稳定。
3. 视频裁剪、切分、变速后，缩略图与波形仍与预览中的源时间一致；上下叠轨分别显示自身内容。
4. 对裁剪且变速的视频分离原声：音频就位、视频原声关闭；分离前后混音、音画同步与导出一致，误差不超过一个时间线帧；波形显示增益不进入声音处理。
5. 对静音片段、静音视频轨、已有静音音轨分别分离，不能意外发声或改变其它片段。移动、删除独立音频后行为符合10.2节。
6. 重复执行、撤销/重做、重启、冲突、失败/取消、轨道上限及素材引用保护全部通过；用户原文件不变。
7. 新固定包完整回归，原生DSH验证直接跳中段、连续拖动播放头、播放/暂停、右键菜单、缩略图及波形实际显示；声音以真实输出录音/监听和导出分析验证，不能只凭按钮或时间数字认定通过。
8. 交付同时报告实现项、自动化证据、原生验收和未测限制。未经新一轮验收，不沿用旧1.0.0包作为本方案发布包。
