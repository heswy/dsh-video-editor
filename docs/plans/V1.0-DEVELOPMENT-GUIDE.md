日期：2026-10-21（Asia/Shanghai）。适用：`v1-plan` 工作树（`codex/v1-plan`，基线 `origin/main` `1aabd6e`）。
状态：**流程文档；用户说“开始”后才按本指南执行**。本文件只定义“怎么开发这个版本”；做什么、做到什么程度见 [V1.0-PLAN.md](V1.0-PLAN.md)（Lead 维护）与 [v1.0 提案](../research/2026-10-21-v1-major-version-proposal.md) §4/§7。

## 0. 一页速览

1. 版本线：`1.0.0-alpha.1 … alpha.N`，全部里程碑验收后发 `1.0.0`；engine client/worker 升 `0.5.0`。当前已安装稳定线为 `0.3.0-alpha.11`，1.0 开发不覆盖它（回滚锚点）。
2. 一个里程碑 = 一个 `1.0.0-alpha.N` 固定 staging + 用户真机验收；**未通过不进下一 M**。M0 是 Go/No-Go 验证门，**默认不发产品 alpha staging**；仅当真实 DSH 验证（@ 引用/预览音频）确需安装时，Lead 构建一次性 `spike` staging（标注非产品候选、可回滚 alpha.11、经用户授权后安装，不纳入 alpha.N 序列、不要求用户功能验收）。
3. 分工固定：Lead 规划/任务卡/评审/staging/验收统筹；用户指定开发会话实现/自测/PR；用户负责安装/重启/真实模型/发布授权与真机验收。
4. 工程真相统一为 `timeline.json`（媒体片段 + AI 场景片段混排），composition 由它单向生成；数据根 `~/Movies/DSH Video/`（用户可见、可配置）。
5. 门禁先绿、树先干净，才允许构建 staging；staging 建了新目录、不覆盖、不改已审候选。
6. 证据落 `artifacts/` 与 `/tmp`（均不入仓，`.gitignore:14` 忽略 `artifacts/`），任务卡只需摘要 + 路径。
7. 不自动跨会话联系（handoff 由用户转发）、不自动安装/重启/合并/发布；每次授权只对当次动作有效。
8. 红线：不 `reset/clean/强推`、不碰用户工程与数据、不读 `~/.dsh/.credentials.yaml`、密钥不进文档/日志/提示词、内部 API 走薄适配层 + 降级。
9. 每层验证只证明该层：组件浏览器/mock/外部 Web 页不能冒充真实 DSH 或真实模型。
10. 交付物：任务卡 + handoff + PR + staging + 验收记录 + 版本/文档同步；缺一项即不完整。

## 3. 任务协议

### 3.1 编号与任务卡

- 编号：`V1-M0-01…`、`V1-M1-01…`、`V1-M2-01…`；任务卡落 `docs/tasks/V1-M<N>-<NN>-<slug>.md`。
- 共享任务板（Agent Teams）与任务卡一一对应：subject 以编号开头；任务卡是范围/验收真相，任务板是调度。
- 状态机：`pending → in_progress → delivered（PR 已开） → verified（verifier/门禁复验） → accepted（用户真机验收）`。**完成 = 有门禁结果 + 证据 + 未测项清单**，不能把计划/进行中标完成。

### 3.2 PR 与 commit

- 一个 PR 对应一个里程碑或一个可独立验收的任务簇；base `main`；提前开 draft 可以，合并必须用户授权。
- 标题：`v1(M1-03): 稳定数据根与一次性迁移`；描述必须含范围/变更/门禁原始数字/证据路径/未测项/回滚/版本与 staging 关系。模板见 §9-C。
- commit：`<type>(<scope>): <summary>`；type ∈ feat/fix/chore/docs/test/refactor；scope ∈ client/host/worker/scripts/docs/version。一 commit 一件事；版本 bump 单独提交 `chore(version): bump 1.0.0-alpha.N`；message/证据中不出现密钥、绝对私人路径。
- 不把无关重构塞进功能/修复 PR；不改历史已审候选文件。

### 3.3 handoff（跨会话唯一通道）

- 里程碑开始、结束各一次；追加到 [docs/handoffs/README.md](../handoffs/README.md) 顶部，并回链任务卡。模板见 §9-B。
- 字段必须覆盖：工作树/分支/base→head、完成项、验证命令与结果（数字）、未测/限制、证据路径、下一步、风险/阻塞、回滚入口。
- Lead 与开发会话之间不自动通信：handoff 由用户粘贴转发；不代为联系其它会话、不发群。

### 3.4 评审清单（Lead + verifier 双层）

1. 范围与任务卡一致，非目标未被顺手实现；写作用域无越界。
2. 契约：`revision` 语义、`expectedRevision + operationId` 幂等、typed error、原子批量、回执/undoHint 未破坏。
3. 边界与失败路径：路径 realpath/allowlist、无任意 URL/路径、失败保留最后有效作品、取消/超时/清理。
4. 迁移与数据：只复制不移动、`migration.json`、失败可重试、备份可回滚；用户作品零回归。
5. 内部 API（`inputTriggers`/`fetch.register`/`sidebarRight`/`remote`）：只在适配层、有启动自检与降级。
6. 测试真实执行（命令+原始数字），新增断言不是删弱旧断言；证据路径可复核；未测项诚实。
7. 版本同步点齐（§6.2）、`RUNTIME_PATHS`/`files`/`check.mjs` 契约同步、文档（STATUS/README/设计/任务卡）一致。
8. 红线检查：无 reset/clean/强推、无密钥/凭据/隐私、无用户数据改动。

## 4. 验证分层与证据

| 层 | 目的 | 命令（在实现树执行） | 通过标准 |
|---|---|---|---|
| L0 语法 | 交付文件可解析 | `node --check index.js && node --check client.js && node --check host/bridge.js && node --check host/routes.js` | 全 exit 0 |
| L1 静态/manifest | 包/patch/exports/files/locale/侧栏契约一致 | `node scripts/check.mjs` | 全 PASS（0.3 基线 54/54，v1 只增） |
| L2 单测/契约 | Client 生命周期、Host 校验、版本门禁、UI 组件 | `node scripts/smoke-client.mjs`（81/81）· `node scripts/check-host.mjs`（68/68）· `node scripts/test-stage-version.mjs`（10/10）· `node scripts/test-ui-polish.mjs /tmp/v1-mN-ui`（27/27）· `cd packages/video-engine-worker && npm test`（56/56） | 全过；ui-polish 用真 Chrome 但属组件契约，不等于真机 |
| L3 真实 staging 链 | 真实 Host+worker+HyperFrames+Chrome/ffmpeg | §5.4 命令 | 结果 `ok=true`/全过 + staging 只读审计 `same=true` + 无外部网络 |
| L4 真机 DSH | 已安装插件内真实面板/会话/预览/导出 | Plugins 页核对版本 + 面板冒烟（用户或获授权 Lead） | 版本准确、`1 of 1 运行中`、清单项通过 |

- L2 基线数字会随 v1 增长：以当次输出为准，并把原始数字写进任务卡/PR。
- L3 只能在**固定 staging**上跑：`test-host-engine` 会先核对 INTEGRITY/Host 摘要（[scripts/lib/staged-host.mjs:138](../../scripts/lib/staged-host.mjs)），拒绝被改动的快照。
- 证据：`test-host-engine` 自动写 `artifacts/p2-b/evidence/engine-run-<iso>.json`；chain/preview 用 `--out artifacts/v1/evidence` 或 `/tmp/v1-mN-*`；截图去标识。**组件浏览器/mock/外部 Web 页不得冒充 L4/L5**（外部页面没有内嵌会话 kit）。
- 每里程碑新增门禁在任务卡列明：timeline schema/op/冲突/undo、迁移与重启、音频 render 校验（AAC/48k/时长/响度）、媒体 Range/穿越、@ resolve 集成。

### 5.2 构建命令（Lead 执行）

```sh
ART="/Users/orange/Orange Field/Matterhorn/dsh-video-editor-worktrees/artifacts"
S="$ART/p2-b/staging-v1.0.0-alpha.1-<rootSha8>"   # 新目录；alpha.N 与提交 SHA 前 7 位

  --engine-commit "$(git rev-parse HEAD)" \
```

- `--bundle-version` 必须与提交内 `package.json` 版本**逐字相等**，否则在创建目录/装依赖前失败（[scripts/stage-dev.mjs:196-208](../../scripts/stage-dev.mjs)、[scripts/lib/stage-version.mjs](../../scripts/lib/stage-version.mjs)）。

- `--node`/`--browser`/`--font` 必须是绝对真实路径：L3 的 `test-conversation-preview` 用 `INTEGRITY.browser` 启动真 Chrome（[scripts/test-conversation-preview.mjs:679](../../scripts/test-conversation-preview.mjs)），未传 `--browser` 的 staging 无法完成该层验证。

### 5.5 安装与重启（仅用户授权后，由用户操作 Plugins 页）

1. **Plugins → Add plugin**，填 `$S/bundle` 绝对路径（开发 link）；2. **Install** → **Enable now**；3. 若 client bundle 变化则重启 DSH（报告阻塞由用户授权/手动重启，不自动退出应用）；4. 重启后核对**实际加载的 client bundle** 已更新（防宿主“新 Host/旧 Client”旧问题，[DEVELOPMENT:39](../DEVELOPMENT.md)），并核对插件页版本 = `1.0.0-alpha.N`、`1 of 1 运行中`，记录来源路径。
- 不手改 profile/`package.json`/`cordis.patch.yml`/`node_modules`；不在 profile 跑 pnpm（[README:157-172](../../README.md)、[DEVELOPMENT:38](../DEVELOPMENT.md)）。

### 5.6 用户真机验收

- 清单见 §9-D；由用户执行、Lead 记录（通过/失败/未测 + 截图证据 + 版本/INTEGRITY）。开发会话不得代填“通过”。
- 里程碑清单从 v1 提案 §8 抽取 + 本里程碑新增项；**所有项通过才算 L4 通过**，未测项须显式列出。
- 不通过：定位→修→从新 main/新候选重建 staging（新目录）→重跑 L1–L3；必要时回滚，不热修已安装候选。

### 5.7 回滚

- 锚点：`artifacts/p2-b/staging-alpha11-51b95dc`（`0.3.0-alpha.11`，INTEGRITY `fd080d27…`）+ 上一 alpha 固定 staging；保留不删。

### 6.1 版本矩阵

### 6.2 alpha.N bump 同步点（漏一处 `check.mjs` 必红）

1. `package.json` 版本（当前 `0.3.0-alpha.11`，`package.json:3`）。
2. `scripts/check.mjs` 版本断言（当前 :138）与名称文案。
3. `scripts/test-stage-version.mjs`：`REVIEWED_BUNDLE_VERSION`（:29）、`ENGINE_COMMIT`（:28，仅用于版本门禁拒绝路径；仓库历史缺失时换任一现存提交即可，不参与成功证据）。
4. `scripts/stage-dev.mjs`：`REVIEWED_ENGINE_PAIRS`（:69-75，新增 0.5.0 对）、`MANAGED_ENGINE_VERSIONS`（:77）。
5. `packages/video-engine-client/package.json`、`packages/video-engine-worker/package.json` 同步 `0.5.0`（两包 `private`，`exports` 保持）。
6. 文档：`README.md` 头部/候选区、`docs/STATUS.md`、`docs/handoffs/README.md`、当前任务卡；`docs/DECISIONS.md` 只新增记录不改历史。
7. 查找漏网：`grep -rn "0\.3\.0-alpha\.11" --exclude-dir=node_modules --exclude-dir=.git .`，以及 `grep -rn "0\.4\.0" packages/*/package.json scripts/stage-dev.mjs`。

顺序：代码/测试 → 版本 bump 独立 commit → `npm run check` + `node scripts/test-stage-version.mjs` → 更新 engine pair → 再构建 staging。

### 6.3 里程碑 → 候选映射（每个 M 一个 staging + 真机验收）

| 里程碑 | 分支/树 | staging | 真机验收重点 |
|---|---|---|---|
| M0 验证门（Go/No-Go） | `codex/v1-m0-validation`（临时） | 默认无产品 staging；真实 DSH 确需时一次性 spike staging（经用户授权） | 媒体逐帧 seek 性能、预览音频、Range/大文件、迁移 SSIM、@ 可用性 |
| M1 存储/工程生命周期 | `codex/v1-m1-storage` | `1.0.0-alpha.1` | 重启 3 次数据在、alpha.10/11 工程迁移、文件夹按钮、上次打开、registry 容错 |
| M2 素材库/媒体管线 | `codex/v1-m2-media` | `alpha.2` | 导入/去重/缩略图/波形、Range 播放、AI `asset.list`、删除在用素材被拒 |
| M3 时间线内核 + 视频轨 | `codex/v1-m3-timeline` | `alpha.3`（内核）/`alpha.4`（UI+导出） | 切/排/精调、预览误差 ≤2 帧、导出 ±1 帧、迁移 SSIM、undo/冲突 |
| M4 音频轨 + 生成音频 | `codex/v1-m4-audio` | `alpha.5` | 旁白+BGM 双轨、A/V ≤1 帧、-16±1 LUFS、生成失败不污染工程、key 不泄漏 |
| M5 @ 引用 + AI 协作 | `codex/v1-m5-refs` | `alpha.6` | 原生 @ 候选/chip、`timeline.resolve`、多轮 3+ 不丢内容、误操作可撤销 |
| M6 发布硬化 | `codex/v1-m6-release` | `alpha.7 …` | 全链路演练、120s 工程、迁移/升级/回滚演练、性能预算 |

M0 默认不出产品 staging（仅真实 DSH 确需时构建一次性 spike staging）；M3 拆 `alpha.3`（内核/视频轨）与 `alpha.4`（UI+导出完整验收）；M6 以 `alpha.7` 收口 1.0.0（必要时可加 alpha.8）。以上已由 Lead 写入 [V1.0-PLAN.md](V1.0-PLAN.md) §5/§9。

### 6.4 1.0.0 发布门禁（全部满足才可发）

1. L1–L3 全绿（含 v1 新增链：timeline/audio/migration/media/@）；2. L4 每个 M 的用户验收记录齐全；3. 迁移演练 + 回滚演练通过（真实用户工程副本）；4. 版本/文档/DECISIONS/已知限制同步；5. staging INTEGRITY 记录 + rootDirty=false；6. 用户明确的发布授权。
发布定义：**通过门禁 + 用户真机清单 + 迁移演练**；合并 PR、构建 staging 都不是发布。

### 6.5 发布后回滚预案

保留最后一个 alpha 固定 staging 与 alpha.11 锚点；发布后出现 S0/S1 问题：停用新版本 → 重装上一 alpha staging → 恢复数据根（仅在已备份且用户同意时）→ 从 main 建 `codex/<hotfix>` 修 → 1.0.1 门禁。发布说明保留“已知限制”（非 30fps/VFR、无 WebAudio 合成、无云同步、无声音克隆、外部分发形态未定义）。

## 7. 沟通与节奏

- **跨会话**：Lead 与开发会话/verifier 不直接发消息，handoff 由用户转发；不自动联系其它会话、不代发。Agent Teams 内（Lead↔teammate）用任务板 + `send_message`。
- **节奏**：里程碑开始（Lead 发任务卡 + 开工 handoff）→ 每日/每次交付（开发会话简短进度：完成/验证/阻塞/未测；Lead 更新任务板）→ 里程碑结束（结束 handoff + PR + staging + 验收）。阻塞立即报（不等待）；>45 分钟无进展也须说明。
- **用户可见摘要**（每次给用户）：见 §9-F，必须写清“已验证/未验证/需要用户做什么/风险”；不把组件或本地 staging 结果说成真机通过。
- **Agent Teams 规则**：任务板 `get→claim→做→complete`；claim 前确认写作用域不与他人重叠；不重复写同一文件；Lead 用 `team_task_list`/`wait_agent` 汇总，等待只对活跃 member；teammate 不嵌套 subagent/workflow；冲突立即停手报告。

## 8. 防护规则（红线，任何任务不得放宽）

- **Git**：不 `reset --hard`、不 `clean -fd`、不强推、不删分支/旧树/staging；不在 `main` 直接开发；不 rebase 已推送分支。
- **用户数据**：不碰 `~/Movies/DSH Video/`、用户工程/作品/旧 staging 内容；测试只用 `/tmp` 或 staging 内副本；迁移前后都做双备份（旧数据根 + 迁移结果各一份，`ditto` 到另一磁盘优先）、只复制不移动、保留可回滚旧目录；不自动清理用户文件。
- **凭据/隐私**：不读 `~/.dsh/.credentials.yaml` 或宿主任何凭据；千问云 key 只从用户配置的 0600 文件读取（按 task-6 指定路径），永不进文档/日志/commit/提示词/回显；不打印环境变量；截图去标识、原始聊天不入库。
- **宿主边界**：不改 DSH 源码/app.asar/profile/session 协议；不手改 profile 或在 profile 跑 pnpm；内部 API（`inputTriggers`/`fetch.register`/`sidebarRight`/`remote`）集中在 client 适配层 + 启动自检 + 失败降级，宿主升级后重跑 `smoke-client` + 真机（[dsh-platform-capabilities:112](../research/2026-10-21-dsh-platform-capabilities.md)）。
- **执行边界**：worker 子进程/脚本执行不等于 OS 沙箱；不把用户素材上传外部；外部音频生成需用户配置 key 且明示 provider；不静默重试写操作、不自动索引磁盘。
- **误操作处置**：立即停止、记录时间/命令/影响、报告 Lead/用户；不操作其它应用撤销用户内容。
