## D036 / 2026-10-21：统一时间线为工程唯一真相（timeline.json），composition 为生成物

accepted（架构）。工程真相从整篇 HTML composition 升级为 `timeline.json`（settings/assets/tracks/clips，整数帧 @30fps）；受控 HTML composition 由 timeline **单向生成**，仅用于预览与导出，不作为编辑真相；不做 composition↔timeline 双向同步。
视觉片段：媒体（视频/图片）、AI 场景（scene HTML，≤48 KiB/场景，受控校验）；音频片段：旁白/配乐/音效 + 视频原声。稳定 ID：`as_`（内容寻址）、`cl_`（永不复用）、`tr_`；split 左段保留原 ID、右段新 ID，回执带 lineage。
所有写操作走 `timeline.apply`（UI 手势与 AI Tool 同一入口）：`expectedRevision + operationId + 原子批量 ops`；回执含 affected/created/deleted、lineage、changeSummary、undoHint。legacy 工程惰性迁移：默认整篇 composition → 一个 scene clip（可回滚），M0 再评估按 Scene 拆分。

## D037 / 2026-10-21：音频供应商可插拔；首个试点千问云，本地 `say` 保底

accepted。v1.0 音频 = 工程级音轨（旁白/配乐/音效）+ 生成/导入资产 + 预览有声 + 导出混音（复用 HyperFrames 0.8.167 原生媒体元素与 `mixAudioTracks`）。
生成能力通过 `AudioProvider` 抽象（capabilities: tts/music/sfx/voice-design；异步 job、取消、重试、错误映射、计费提示）；首个试点 **千问云（qianwenai.com）**，本地 macOS `say` 作为零配置旁白保底。**v1 不引入第二家音频供应商**：Fun-Music 音乐生成邀测未开通期间 BGM 用用户上传兜底；开通后音乐生成走同一 provider 家族（与 TTS 同一调用逻辑）。
密钥规则：用户提供、存本机 0600 配置（v1 数据根 `settings/` 或环境变量），Host/worker 使用；**永不**进入仓库、文档、日志、提示词、模型上下文；不读取宿主凭据。第三方条款/计价以官方为准，使用前向用户展示。

## D038 / 2026-10-21：工程数据根迁出 staging，默认 `~/Movies/DSH Video/`

accepted。当前数据（projects/registry/session-state/asset-inbox）位于按版本新建的 staging 目录，跨版本不迁移导致旧工程不可见（alpha.9/alpha.10 已发生）。v1.0 起：
- 数据根默认 **`~/Movies/DSH Video/`**（用户可见、文件夹按钮直达），`DSH_VIDEO_DATA_ROOT` 可覆盖（外置盘）；
- 一次性迁移旧 staging 工程（**只复制不移动**、旧目录保留、`migration.json` 记录、失败可重试、可回滚）；
- registry 单工程容错（quarantine 不再让整桥 `E_CONFIGURATION`）、session-state 备份/重建；
- `ui-state.json` 持久化上次打开工程/面板比例（localStorage 因宿主随机端口不可靠）；
- `project.path/reveal`（UI-only、Host 权威路径）+ 工程菜单「在 Finder 中显示 / 复制路径」；
- 默认限额：单文件 2 GiB、单工程 8 GiB，低磁盘预警；导出保存到工程 `exports/`。

## D039 / 2026-10-21：@ 引用使用宿主内部 `inputTriggers`（带降级）

accepted。需求 4 采用宿主客户端内部服务 `ctx.inputTriggers.registerSource()` 注册插件 `@` 候选（片段/素材/场景/区间），插入 chip 并序列化为稳定 token（`@clip:cl_xxx` / `@asset:as_xxx` / `@range:120-300`）；Host 侧 `timeline.resolve` 解析并对歧义返回候选；system prompt 说明语法。
风险：内部 API 无 semver、宿主 nightly 可能变化；实现必须集中在薄适配层 + 启动自检 + 失败降级为「插件内引用 chip + 复制 token + AI 主动 inspect」；不修改宿主 DOM/会话协议。M0 真机补充：序列化文本若以裸 `@token` 形式输出会被宿主 `@file` userText 规则当作文件引用截断，必须用行内代码 token，或注册自定义 `ctx.uiConversation.userText` 规则渲染自己的 chip（M5 实现/复验）。另：引用必须先 resolve 到真实项目/稳定 ID 再动作；解析失败/歧义只给一行提示+重选，不使用长篇 `ask_user_question` 追问卡；M5 需真机验证嵌入会话中的确认/提问卡按钮可点性，必要时用产品自有确认 UI。

## D040 / 2026-10-21：v1.0 开发流程与工作区（Lead 统筹）

accepted（流程）。用户在本次大版本中指定 Lead（主会话）统筹：规划/任务卡/评审/staging 构建/验收组织/发布统筹；开发会话按任务卡实现/自测/PR；用户负责真机验收与安装/重启/发布授权。流程细则见 `docs/plans/V1.0-DEVELOPMENT-GUIDE.md`：
- worktree/分支：`v1-plan`、`v1-m0-validation`、`v1-m1-storage`…`v1-m6-release`；分支 `codex/v1-*`；staging 用一次性发布树；main 仍是唯一长期分支，PR 回 main。
- 里程碑：M0 验证门（Go/No-Go）→ M1 存储 → M2 素材 → M3 时间线 → M4 音频 → M5 @/协作 → M6 发布；每个 M 一个 `1.0.0-alpha.N` staging + 用户真机验收；未通过不进下一 M。
- 每任务：任务卡（范围/非目标/写作用域/验收/验证/证据/回滚/风险）+ handoff + PR；L0–L5 分层验证；不自动安装/重启/合并/发布。
- 红线：不 reset/clean/强推；不碰用户数据；不读宿主凭据；密钥不入库；内部 API 隔离降级。
