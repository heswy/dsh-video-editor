## 1. 目标与完成定义

### 1.1 版本目标

把 DSH Video 从「对话生成 + 只读预览」扩展为 **AI 可协作的统一时间线剪辑台**，具备发布能力：

1. **生成音频**：旁白 / BGM / 音效可生成（供应商可插拔，首个试点千问云）+ 可导入 + 上音轨 + 预览有声 + 导出有声。
2. **视频轨 + 音频轨 + 基本剪辑**：用户可切分/裁剪/排序/删除/移动/换轨/调音量/淡入淡出；AI 能对片段做同样操作（基于稳定 ID），长视频切段后可继续操作。
3. **素材库**：按工程导入视频/图片/音频，前端素材库页面，AI 可列出/引用素材。
4. **@ 引用**：输入框 @ 可引用片段/素材/场景；AI 解析稳定 token，位置描述必须 resolve。
5. **存储可靠**：工程数据根迁出 staging 到 `~/Movies/DSH Video/`；重启/升级不丢；每个工程「文件夹」按钮直达；上次打开工程可恢复。

### 1.2 完成定义（1.0.0 发布门槛）

- 第 7 节所有里程碑的**用户真机验收**通过，且无 S0/S1 未关闭风险。
- 用户视角闭环：**新建 → 导入长视频 → 切 3 段 → 重排/精调 → 生成旁白+BGM → 预览 → 导出有声 MP4 → 重启/升级后工程仍在**。
- 旧 AI 生成作品（alpha 工程）可打开、迁移、播放、导出，视觉零回归。
- 发布门禁（自动 + 真链 + 真机）全部通过；数据迁移演练与回滚演练通过；文档/记忆/版本号同步完成。

## 3. 范围

### 3.1 v1.0 必须（Must）

**时间线内核**
- `timeline.json` schema `dsh-video/timeline@1`：settings/assets/tracks/clips；整数帧 @30fps；内容寻址资产；稳定 ID（`as_` / `cl_` / `tr_`）。
- 生成 composition 管线（确定性序列化）+ revision v2 + history/undo v2 + legacy 迁移。
- 操作：`clip.split/trim/delete/move/reorder/insert/duplicate/speed/replace`、`track.add/update/remove`、`timeline.settings`、视频原声、crossfade；`timeline.inspect/apply/resolve`（expectedRevision/operationId/原子批量/dryRun/回执 lineage/summary/undoHint）。
- AI 场景片段：`scene.compose/scene.inspect`（每场景 ≤48 KiB，受控校验）；整片生成改为多场景提交。
- 预览：单 iframe 生成 composition + 媒体/音频同步 + 媒体 Range 路由；播放头/时间/seek 与时间线双向。
- 导出：HyperFrames render（媒体 + 音频混流）+ ffprobe 校验 `v:0`/`a:0` + 超时自适应 + `audioFailures` 诊断。

**素材**
- 导入视频/图片/音频（文件选择/拖拽）→ 流式上传 → ffprobe → 内容寻址 assets → timeline assets；格式白名单与限额。
- 派生缓存：缩略图 / 波形 / 代理（非 30fps / 大素材）；可重建、不进 revision。
- 素材库页面：按工程、网格、筛选、搜索、详情、删除引用检查；AI `asset.list`。

**音频**
- 音轨/片段模型：轨道 gain/mute/role；clip 音量、淡入淡出、速度；旁白/配乐/音效三轨。
- 生成：`AudioProvider` 适配层 + 千问云 provider + 本地 `say`；异步 job、取消、重试、费用提示；产物自动入素材库。
- 预览有声（自动播放兜底）；导出 AAC 48k + loudnorm + 音画偏移验收。

**工程与存储**
- 数据根迁移 + 旧 staging 工程一次性导入（复制不移动、可回滚）。
- registry 单工程容错（quarantine）、session-state 备份/重建、`ui-state.json`（上次打开/面板比例/时间线状态）。
- `project.path` / `project.reveal` + 顶栏工程菜单「在 Finder 中显示 / 复制路径」；保存状态指示。
- 导出产物保存到工程 `exports/`（建议项，见 §13）。

**引用与协作**
- `inputTriggers` source（片段/素材/场景/区间）+ chip + 复制 token；`timeline.resolve`；system prompt 语法说明。
- AI 变更回执/变更卡/撤销；UI 与 AI 单写者队列 + 冲突恢复 UX；AI 剪辑指令测试集。

**发布硬化**
- 性能/内存预算、预览/导出一致性、120s 工程实测、失败/取消/超时路径。
- 版本/打包/文档/记忆/发布门禁；迁移与回滚演练；真 DSH 安装验收。

### 3.2 明确不做（Won't，v1.0）

- 专业 NLE 全套：关键帧、蒙版、调色、多机位、字幕轨、变速曲线、复杂转场库、音频 EQ/压缩。
- 多用户实时协同 / 云渲染 / 云同步。
- WebCodecs / ffmpeg.wasm 自研合成（列 v1.1+ 备选）。
- 程序化 Web Audio 音乐经 render 进片（render 不采集；v1 不做）。
- 声音克隆、多语言配音矩阵、自动字幕（v1.1+）。
- 双向 composition↔timeline 同步、把 HTML 当编辑真相。
- 自动扫描/索引用户全盘素材、跨工程语义检索。
- 改宿主 DOM/协议、读宿主凭据、伪造 `dsh-session:` 引用。

### 3.3 延后（v1.1+ 候选）

4K/HEVC/60fps 原生支持；按 Scene 拆分 legacy 迁移；beat sync/自动踩点；自动 ducking；音频波形关键帧；OTIO/FCPXML 导出；本地开源音频模型；多工程模板。

## 4. 技术架构（一页）

```
UI（client.js）
 ├─ 时间线/片条组件、素材库、引用 chip、变更卡、文件夹/保存状态
 ├─ 预览 iframe（generated composition + 扩展 runtime：media 同步）
 └─ 宿主原生 Composer（@ source 注册）+ AI 对话
        │ Host /api/dsh-video/*（鉴权）+ public exact routes（媒体/快照）
        ▼
Host（host/*.js）
 ├─ VideoBridge（单一业务入口：UI + Tool）
 ├─ 数据根/registry/迁移/reveal/媒体 Range 路由/音频 provider 密钥
 └─ worker supervisor（独立 Node 进程）
        ▼
Engine worker（packages/video-engine-worker/src）
 ├─ timeline 真相读写、op 引擎、生成 composition、revision/history
 ├─ asset 导入/探测/派生缓存（ffmpeg）
 ├─ 音频 job（provider 调用、say、取消/重试）
 └─ HyperFrames 预览快照 / render（媒体 + 音频混流）+ ffprobe 校验
        ▼
数据根 ~/Movies/DSH Video/
 projects/<id>/{timeline.json,assets/,scenes/,exports/,.dsh-video/{history,legacy,cache}}
 registry.json / session-state.json / ui-state.json / settings/（provider key 0600）
```

**关键契约**（详见时间线架构调研 §3–§5）：
- revision = 真相文件内容哈希；所有写带 `expectedRevision + operationId`；单写者队列；冲突显式。
- 生成 composition 只读派生；用户/AI 都不能直接写它。
- 场景 HTML 受控校验（禁媒体/外部 URL，≤48 KiB）；生成 composition 由 worker 生成、允许媒体元素。
- 音频/媒体不写入快照；走工程级内容寻址路由（Range）。
- 数据根与 staging 解耦；staging 只放代码与默认配置。

| M5-04 | 回执/提示 UI | 变更卡/toast/高亮/撤销；历史面板；AI 操作可见可解释；引用失效/解析失败用一行提示+重选，不触发宿主长追问卡 |
| M5-05 | 协作冲突 | UI/AI 单写者、冲突重读、UI 锁、恢复 UX；多轮不丢内容 |
| M5-06 | AI 测试集 | 30 条中文剪辑指令，一次成功率 ≥95%；失败全部可解释；新增：引用+无指令、引用失效、假引用三类用例 |
| M5-08 | 嵌入会话交互 | 验证 `ask_user_question`/确认卡在插件嵌入会话中的按钮可点性与布局；不可用则用产品自有简洁确认 UI 替代 |
| M5-07 | 门禁 | 引用解析 100%；真实模型 3+ 轮；真实 DSH 验收 |

### 6.2 分支与提交

- 分支：`codex/v1-plan`、`codex/v1-m0-validation`、`codex/v1-m1-storage`、`codex/v1-m2-media`、`codex/v1-m3-timeline`、`codex/v1-m4-audio`、`codex/v1-m5-refs`、`codex/v1-m6-release`；发布树 `v1-release-alpha.N` 用 detached HEAD，不建长期分支。
- 每个里程碑从**最新 main** 建分支；PR 回 main；不在 main 直接开发；不长期维护 v1 集成分支（遵循 DEVELOPMENT 的 main 唯一长期分支规则）。
- commit 规范：`feat(v1-m3): ...` / `fix(v1-m1): ...` / `docs(v1): ...`；一个任务一个 commit 或少量逻辑提交；不夹带无关重构。
- 每次 PR：任务卡链接 + 门禁结果 + 未测项 + 回滚说明。

### 6.3 建立命令（可在“开始”后直接执行）


### 6.4 并行规则

- 同一 worktree 同一时间只有一个写入会话。
- 可并行流：M1（Host/config/storage）与 M2（worker/assets/UI 素材库）在**文件写作用域互斥**时；M3 协议层与 M4 provider 适配层可并行（接口先冻结）。
- 并行任务必须在任务板标注 `write_scopes`；冲突由 Lead 裁决；不共享未提交代码。

## 7. 开发方式与协作（摘要，详见开发运行指南）

### 7.1 角色

| 角色 | 职责 |
|---|---|
| **Lead（本会话）** | 版本规划、任务卡、架构/契约评审、代码评审、staging 构建、验收组织、风险与发布决定；不直接实现（除非用户明确指派） |
| **开发会话** | 按任务卡实现、自测、真链验证、修复、交 PR；只写任务范围内文件；维护任务记录与 handoff |
| **独立 verifier（可选）** | 对里程碑候选做独立复验（真 Chrome/真 staging），出 PASS/FAIL |
| **用户** | 真机验收、安装/重启/发布授权、产品决策 |

### 7.2 每个里程碑的固定节奏

```
Lead 下发任务卡（含契约/验收/写作用域）
  → 开发会话建 worktree/分支 → 实现 + 自测 + 真链验证
  → PR 到 main（门禁结果 + 未测项）→ Lead 评审/合并
  → Lead 构建 1.0.0-alpha.N 固定 staging（记录 INTEGRITY）
  → 用户 Plugins 页安装/重启 → 按验收矩阵真机验收
  → 通过 → 下一里程碑；不通过 → 修复任务卡（新分支）→ 重新 staging
```

### 7.3 沟通与 handoff

- 里程碑开始：任务卡 + 范围/非目标 + 风险提示。
- 里程碑结束：handoff（base/head、范围、验证证据、未测、下一步、回滚入口）。
- 每日/每阶段：Lead 汇总进度与阻塞；用户只看三件事：**能看什么、能改什么、下一步要你做什么**。
- 阻塞立即上报；不跨会话自动联系（由用户转发或 Lead 调度）。

### 7.4 Agent Teams 使用（可选）

- 仅在任务可独立切分时启用；每个 member 有互斥 `write_scopes` 与任务板卡片。
- Member 不 commit/push；Lead 统一整理与提交（或明确指派一个 owner 提交）。
- 子任务完成后 Lead 必须复核关键结论/文件，再合并到里程碑分支。
- 不把需要用户真机/模型请求的验收交给 member 自行宣称。

## 8. 验收体系

### 8.1 分层验证（每任务/每里程碑）

1. **静态/契约**：`node scripts/check.mjs`、manifest/patch/exports、schema 校验。
2. **单测/契约**：client smoke、host check、worker/engine 单测、新增 timeline/asset/audio 单测。
3. **真链（staging）**：`test-host-engine`、`test-canvas-chain`、`test-conversation-chain`、`test-conversation-preview`、`test-stage-version`。
4. **真机 DSH**：Plugins 安装、真实页面、真实会话、真实渲染/导出。
5. **真实模型/真实素材**：模型多轮、真实 20s/120s 工程、真实素材导入。

### 8.2 用户验收方式

- Lead 给出**候选 staging 路径 + INTEGRITY + 安装步骤 + 验收清单**；用户安装/重启后按清单操作并反馈。
- 每次验收记录：版本/提交/INTEGRITY/通过项/失败项/截图或文件（脱敏）/结论。
- 详细矩阵见 [V1.0-ACCEPTANCE.md](V1.0-ACCEPTANCE.md)。

- 安装回滚：回装上一 staging（alpha.11 或最后通过的 alpha.N）。

- 代码回滚：main 正常 revert；不回滚用户数据。

## 13. 待确认（不阻塞 M0 启动）

1. **素材格式/上限**：默认 `mp4/mov/m4v/webm + mp3/wav/m4a/aac/flac + png/jpg`；单文件 2 GiB、单工程 8 GiB、30fps CFR；4K/HEVC/60fps 原生支持延后 v1.1（导入可选转 1080p/30 代理）。
